Review in this checkout. Do not change code, tickets or PRs, and do not start other agents, apart from what /run-review itself runs. Only allowlisted tools and commands run, and anything else is denied. Run shell commands one at a time. If a denial stops the review, report `RESULT: BLOCKED` with the denied command rather than working around it. User and plugin skills do not load in this session, so to run `run-review`, read `~/.claude/skills/run-review/SKILL.md` and follow it, using the given target and any `--spec` as `$ARGUMENTS`. Where it invokes `/mattpocock-skills:code-review`, glob `~/.claude/plugins/cache/*/mattpocock-skills/*/skills/engineering/code-review/SKILL.md`, read the highest version and follow it instead; with no match, that review is unavailable. Shell commands run from this checkout's root: `git -C` and `cd` before `git` are denied.

1. If the task below gives a target (a PR number, commit range or path), run the `run-review` skill on exactly that target and any `--spec`, wait for its findings to arrive, then go to step 5. A commit range with no changes gets `RESULT: BLOCKED` with the reason instead, then step 5. Otherwise run `git fetch origin` and review the current branch against `origin/<default-branch>`, as follows.
2. Report `RESULT: BLOCKED` with the reason, without reviewing, if you are on the base branch, cannot determine the base, there are no commits, uncommitted changes or untracked files to review, or the task gives `--spec` and the branch has no commits ahead of the base, then go to step 5.
3. If the branch has commits ahead of the base, run the `run-review` skill on `<base>...HEAD` with any `--spec`. Wait for its findings to arrive; the review runs in the background.
4. Check `git status --porcelain`. If it lists tracked changes, run `run-review` again with no target. If it lists untracked files, run `run-review` on those paths, because a no-target run skips them. Merge the findings of every pass axis by axis, keeping the axes separate, remove duplicates within an axis, and take the worst verdict: BLOCKED outranks FAIL, and FAIL outranks PASS. An axis skipped on one pass keeps the result of the pass that ran it, and the report says that Standards and Spec did not cover the uncommitted or untracked work.
5. Write the full report to `~/.cache/hc-reviews/<repo>-<name>.md`, where `<repo>` is the checkout's folder name and `<name>` is the target, or the branch if there is none, with each `/` replaced by `-`. For a path target with committed code, say in the report that older findings are marked Pre-existing, so PASS is not a full review of the file.
6. Send your parent one line with `hc send`, to the address in the `hc` tag around this message: the verdict, finding counts and the report path.
7. Stay open for follow-ups.
